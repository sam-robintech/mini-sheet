원본: tasks/plan.md · 입력: SPEC.md

아키텍처 다이어그램

화살표는 "의존한다" 방향이다(A → B: A 가 B 에 기댄다). 층은 의존 깊이다. 상자에 마우스를 올리면 책임과 관련 결정(D)·위험(R)이 보이고, 그 상자의 화살표가 붉게 표시된다.

개요

index.html 하나를 file:// 로 열어 쓰는 26열×100행 계산표를 만든다. 칸의 원문을 숫자·문자열·수식·빈 칸으로 읽고, 수식은 직접 만든 토큰 분석기·구문 분석기·계산기로 계산한다(eval 없음). 표 모듈이 칸 사이의 의존 그래프를 들고 있어 바뀐 칸에 기대는 칸만 순서대로 다시 계산하고 순환은 #CIRC! 로 표시한다. 칸 고르기, 되돌리기, 복사·붙여 넣기, 저장, CSV 만들기는 각각 DOM 을 모르는 규칙 모듈이 계산하고, src/app.js 하나가 DOM·키보드·마우스·localStorage·내려받기를 이 모듈들에 잇는다. 규칙 모듈은 node:test 단위 테스트로, 화면 동작은 Playwright e2e 로 확인한다.

기존 코드 파악

  • 새 프로젝트다. 저장소에는 idea.md, spec-standard.md, SPEC.md, .gitignore 만 있고 src/, tests/, e2e/, package.json 은 아직 없다.
  • 따를 관례는 SPEC.md 의 작업 환경과 spec-standard.md 에서 온다.
    • 브라우저 전역 스크립트(ES2020). 파일마다 IIFE 로 감싸 전역 객체 하나만 내고(Address, Value, ...), 끝에서 if (typeof module !== 'undefined') module.exports = ... 로 내보낸다.
    • index.html 의 스크립트 순서는 address → value → functions → formula → sheet → selection → history → clipboard → storage → csv → app 으로 고정이다. 의존은 앞에 읽는 파일로만 향해야 한다.
    • 들여쓰기 2칸, 작은따옴표, 세미콜론. 함수·변수는 카멜, 상수는 대문자 밑줄, 오류 값 상수는 ERR_ 로 시작. 칸 주소 문자열은 늘 대문자.
    • 단위 테스트는 tests/<모듈>.test.js, e2e 는 e2e/<기능>.spec.js. 테스트 이름은 영어 문장.
    • e2e 가 찾는 고리: [data-cell="A1"], .active, .selected, #name-box, #formula-input, #cell-editor, #download-csv.
  • .gitignore 에 node_modules/, test-results/, playwright-report/ 가 이미 있다.

아키텍처 결정

번호결정이유
D1모듈 꼴: 파일마다 var X = (function () { ... })(); 와 끝의 if (typeof module !== 'undefined') module.exports = X;. 다른 모듈은 IIFE 맨 위에서 var Value_ = typeof module !== 'undefined' ? require('./value.js') : Value; 꼴로 얻는다. 의존은 index.html 에서 앞에 읽는 파일로만 향한다(C1~C12 의존 표가 이를 지킨다).SPEC 작업 환경(전역 스크립트, ES 모듈 금지)과 Node require 단위 테스트를 함께 만족한다. 고정 스크립트 순서와 의존 방향을 맞춰 순환을 막는다.
D2DOM·localStorage·Blob·document 는 C11 App 만 만진다. C1~C10 은 입력→출력만 하는 순수 규칙 모듈이다. C9 Storage 는 getItem/setItem 을 가진 저장소 객체를 인자로 받는다.커버리지 90% 대상이 src/app.js 를 뺀 전부이고, 단위 테스트가 DOM 없이 돌아야 한다(SPEC 검증 수단).
D3칸 값 모양(C2·C3·C4·C5·C10 이 공유): { type: 'empty' }, { type: 'number', value: n }, { type: 'string', value: s }, { type: 'bool', value: b }, { type: 'error', value: '#DIV/0!' }. 오류 값 상수는 Value.ERR_DIV0, ERR_NAME, ERR_REF, ERR_VALUE, ERR_CIRC, ERR_SYNTAX(#ERROR!). 바꾸기 함수 Value.toNumber(v) 는 빈 칸 0, 참 1, 거짓 0, 숫자로 읽히지 않는 문자열은 #VALUE! 오류 값을 돌려준다. Value.toText(v) 는 빈 칸 ''.다섯 모듈이 같은 값을 주고받는다. 오류를 예외가 아닌 값으로 다뤄 G4 전파를 단순한 "첫 오류 반환" 규칙으로 만든다.
D4원문 해석 Value.parseRaw(raw) → { kind: 'empty'|'number'|'string'|'formula', value }. 숫자는 앞뒤 공백을 뺀 글자가 /^[+-]?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?$/ 에 맞을 때만(12a 는 문자열). 보이는 글자 Value.display(v): 숫자는 String(Number(n.toPrecision(15))), 참/거짓은 TRUE/FALSE, 오류는 그 글자, 빈 칸은 ''. 정렬 종류 Value.align(v) 는 숫자만 right, 나머지 left.G2·G10·AC5·AC21 을 한곳에서 정해 C10 Csv 와 C11 App 이 같은 글자를 쓰게 한다.
D5C4 Formula 공개 API: parse(text) → { ast, refs } 또는 문법이 틀리면 { error: '#ERROR!' }. refs 는 의존할 주소 문자열 목록(범위는 펼친 주소, 표 밖 참조는 넣지 않음). evaluate(ast, ctx) → 칸 값(D3). ctx.get(addr) 이 칸 값을 준다. shift(text, dCol, dRow) → 옮긴 수식 원문. 토큰: 숫자, 큰따옴표 문자열("" 는 따옴표 하나), 참조($?[A-Za-z]+$?\d+), :, 함수 이름+(, ,, 연산자, 괄호, 오류 글자(#REF! 등 여섯 개). AST 노드: num, str, err, ref, range, unary, binary, call.C5 Sheet 와 C8 Clipboard 가 함께 쓰는 계약이다. AC16 의 =#REF! 가 다시 읽혀 #REF! 값을 내려면 오류 글자가 토큰이어야 한다.
D6우선순위는 낮은 것부터 비교(= <> < > <= >=) < & < + - < * / < ^ < 단항 - +. 이항 연산은 모두 왼쪽부터 묶는다(^ 포함). 단항은 ^ 보다 먼저 묶으므로 =-2^2 는 (-2)^2 = 4. 계산 결과가 Infinity/NaN 이면 #VALUE!, 나눗수가 0 이면 #DIV/0!. 종류가 다른 값의 비교는 Q1 의 가정을 따른다.G6·AC9 을 그대로 옮긴 것이다. 재귀 하강 파서의 단계 순서로 구현한다.
D7오류 전파 순서: 이항 연산은 왼쪽 피연산자 오류를 먼저, 그다음 오른쪽 오류를 돌려준다. 함수는 인자를 왼쪽부터 보고 처음 만난 오류를 돌려준다. 범위 안의 오류도 G4 대로 그대로 돌려준다. 표 밖 참조(AA1, A101)는 파싱에 성공하고 계산 때 #REF!. 없는 함수는 파싱에 성공하고 계산 때 #NAME?. IF 는 조건을 먼저 계산하고 고른 쪽 인자만 계산한다(엑셀과 같음).여러 오류가 섞일 때 결과를 하나로 정해야 테스트 기대 값이 정해진다. IF 의 고르지 않은 쪽 오류는 퍼지지 않는다(가정, Q2 참고).
D8C3 Functions API: Functions.call(name, args, evalArg). 인자는 미리 계산하지 않고 { kind: 'value', value } 또는 { kind: 'range', values: [...] } 로 넘기거나, IF 는 evalArg(i) 로 필요한 인자만 계산한다. 범위 안의 문자열·빈 칸·참/거짓은 건너뛰고, 인자로 직접 준 문자열은 #VALUE!(G8). ROUND 는 x * 10^d 를 toPrecision(15) 로 정리한 뒤 부호를 떼고 Math.floor(|y| + 0.5) 를 하고 부호를 다시 붙여 10^d 로 나눈다.G8 의 "범위 안"과 "직접 준 인자"를 구별하려면 인자가 범위였는지 알아야 한다. ROUND 규칙은 G8 의 2.345 예를 지키는 방법이다.
D9C5 Sheet API: Sheet.create() → { setRaw(addr, raw) → 값이 바뀐 주소 목록, setMany([{addr, raw}]) → 같음, getRaw(addr), getValue(addr), getDisplay(addr), entries() → 원문이 있는 [addr, raw] 목록, loadAll(cellsMap), evalCount }. evalCount 는 수식 계산 횟수 누적 값이고 테스트에서 읽는다. 다시 계산은 바뀐 칸들에서 역방향 그래프를 따라 기대는 칸 집합을 모으고, 그 부분 그래프에서 Tarjan 강한 연결 요소를 찾아 크기 2 이상이거나 자기 참조인 요소의 칸을 #CIRC! 로 두고, 나머지는 위상 순서로 한 번씩 계산한다. 순환 칸에 기대는 칸은 계산하면서 G4 로 #CIRC! 를 받는다.AC15 의 "계산 횟수 확인"이 공개 계약이어야 한다. 순환 안의 칸과 순환 아래의 칸을 구별해야 IF 같은 경우에 값이 맞다(D7). 순환을 끊으면 같은 절차로 제 값이 돌아온다(G17).
D10C6 Selection 상태: { active: {col,row}, focus: {col,row} }, 고른 범위는 두 칸이 이루는 사각형. move(state, dir) 는 범위를 활성 칸 하나로 접고 옮긴다(Enter=down, Shift+Enter=up, Tab=right, Shift+Tab=left 도 같은 함수). extend(state, dir) 는 focus 만 옮긴다. extendTo(state, cell) 은 Shift+클릭. select(cell). rangeText(state) 는 한 칸이면 A1, 범위면 A1:B3. 모두 표 끝에서 멈춘다.G11·AC3·AC4 를 DOM 없이 시험한다.
D11C7 History: History.create(limit = 100) → { push(step), undo() → step|null, redo() → step|null, canUndo, canRedo }. 단계는 [{ addr, before, after }] 이고 before 와 after 가 모두 같으면 쌓지 않는다. C11 App 은 확정 한 번·지우기 한 번·붙여 넣기 한 번을 한 단계로 만들고, undo 는 before 를, redo 는 after 를 C5 setMany 로 넣는다. C8 Clipboard 는 copy(getRaw, range) → { rows, cols, origin, raws }, paste(clip, target) → [{ addr, raw }] 를 돌려줄 뿐 표를 바꾸지 않는다.표를 바꾸는 길을 C11 App → C5 Sheet 하나로 모아 되돌리기·저장·화면 갱신이 늘 같이 일어나게 한다.
D12기술 스택은 SPEC 작업 환경 그대로다: HTML·CSS·JavaScript(ES2020 브라우저 전역 스크립트), 프레임워크·번들러 없음, Node.js LTS 24.x 와 node:test(단위), @playwright/test 1.x 와 Chromium(e2e), 데이터는 localStorage, 서버 없음. 테스트 도구: package.json 의 scripts 는 SPEC 그대로(test, test:coverage, e2e), devDependency 는 @playwright/test 하나. playwright.config.js 는 맨 위에서 process.env.PLAYWRIGHT_BROWSERS_PATH = '0', testDir: 'e2e', Chromium 프로젝트 하나, 웹 서버 없음. e2e 는 pathToFileURL(path.resolve('index.html')).href 로 열고 시작할 때 localStorage 를 비운다. AC22 는 page.on('request') 로 file: 밖 요청을 센다. 키 조합은 ControlOrMeta 를 써서 맥과 다른 운영체제에서 같은 테스트가 돈다.SPEC 검증 수단과 작업 환경을 그대로 따른다. C11 App 과 C12 Page 는 e2e 로만 확인한다(D2).
D13화면: C11 App 은 <table> 하나에 2600개 <td data-cell> 를 처음 한 번 만들고, 이후에는 C5 가 돌려준 바뀐 주소의 칸만 글자와 정렬 클래스를 고친다. 고치기는 #cell-editor 입력 상자 하나를 활성 칸 위에 겹쳐 쓴다. 수식 입력줄 #formula-input 은 활성 칸 원문을 보여 주고, 거기서 고치면 같은 확정 경로를 탄다.2600칸을 매번 다시 그리지 않아 빠르고, e2e 고리([data-cell], #cell-editor)를 지킨다.
D14저장과 불러오기: C11 App 이 원문이 바뀌는 모든 경로(확정·지우기·붙여 넣기·되돌리기·다시 하기) 뒤에 Storage.save(localStorage, sheet.entries()) 를 부른다. 열 때 Storage.load(localStorage) 결과를 C5 loadAll 로 넣고 전체를 다시 계산한다. CSV 는 C11 App 이 C5 getDisplay 로 보이는 값 맵을 만들어 Csv.build(map) 에 넘기고, 결과를 Blob + <a download="sheet.csv"> 로 내려받는다.G15·G16 을 따르고 C9·C10 을 순수하게 둔다(D2).

위험

번호위험영향대응
R1playwright.config.js 안에서 넣은 PLAYWRIGHT_BROWSERS_PATH 가 브라우저 경로에 반영되지 않을 수 있다(SPEC G18, D12).중반영되지 않으면 PLAYWRIGHT_BROWSERS_PATH=0 npm run e2e 로 실행한다. 브라우저 설치와 실행 확인은 mvp-builder 가 한다.
R2file:// 페이지에서 Blob URL 내려받기가 Playwright download 이벤트로 잡히지 않을 수 있다(C11, D14).중e2e csv.spec.js 는 page.waitForEvent('download') 로 받고 내용을 읽어 비교한다. 잡히지 않으면 원인을 열린 질문으로 올린다. CSV 내용 규칙은 C10 단위 테스트가 따로 지킨다.
R3수식 옮기기를 정규식으로 하면 문자열 안의 "A1" 이나 함수 이름(LOG10 같은 꼴)까지 바뀐다(C4, C8).중D5 대로 토큰 단위로 옮기고, 문자열 토큰은 그대로 둔다. 단위 테스트에 ="A1"&A1 꼴을 넣는다.
R4넓은 범위(SUM(A1:Z100))가 의존 간선 2600개를 만들고, 불러오기 때 전체 다시 계산이 느려질 수 있다(C5).하표 크기가 2600칸으로 고정이라 간선 수에 상한이 있다. 다시 계산은 기대는 칸 집합 안에서 칸마다 한 번이다(D9).
R5브라우저 기본 동작(Tab 의 포커스 이동, Ctrl+Z 의 입력 상자 되돌리기, F2, Backspace)과 앱 키 처리가 겹친다(C11).중고친 상태가 아닐 때 앱이 처리한 키는 preventDefault 한다. 고치는 중에는 Enter·Tab·Esc 만 가로챈다(G12). e2e keyboard.spec.js, edit.spec.js, undo.spec.js 로 확인한다.
R6오류가 여러 개 섞인 수식, IF 의 고르지 않은 쪽 오류, 숫자와 문자열 비교처럼 SPEC 이 정하지 않은 경우의 결과가 사람의 기대와 다를 수 있다(C3, C4, D7).중D7 로 순서를 정하고 열린 질문 Q1·Q2 로 올린다. 정한 규칙은 단위 테스트로 묶어 바꿀 때 바로 드러나게 한다.
R7--experimental-test-coverage 의 옵션 이름이나 출력이 Node 24 와 25 사이에서 달라질 수 있다(D12, SPEC G19).하SPEC 의 명령을 그대로 쓰고, 실패하면 Node 버전과 함께 보고한다.
R8유효숫자 15자리 정리(D4)는 아주 크거나 작은 수를 1e+21 처럼 지수 꼴로 보인다(C2).하SPEC 은 그 밖의 서식이 없다고 했으므로 그대로 둔다. AC21 의 예만 단위 테스트로 지킨다.
